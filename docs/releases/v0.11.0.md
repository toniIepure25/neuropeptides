# ntx v0.11.0 — 2026-11-14

Cluster-aware, auditable calibration. The report remains descriptive only, but it
now treats repeated experiments for one hypothesis as dependent, exposes where the
analysis is underpowered, and makes its analysis choices and data attrition
inspectable. Database schema v6 and ledger export v3 are unchanged.

## Highlights

- **Hypothesis clustering by default.** `ntx ledger calibration` resamples whole
  hypotheses in its bootstrap instead of pretending every experiment is
  independent. `--cluster experiment` restores independent-experiment resampling
  for comparison.
- **Explicit power boundary.** `n_clusters` is reported and bootstrap intervals
  require both `n >= 10` and `n_clusters >= 10`. `underpowered_reasons` distinguishes
  `rows<10` from `clusters<10`; a single hypothesis with many outcomes is still one
  cluster.
- **Subgroups and precision.** `by_kind` and `by_design` show Brier, ECE, accuracy
  and cluster counts only with at least 3 rows and 2 clusters. CI precision counts
  classify consistent, imprecise, inconsistent and missing intervals.
- **Attrition and corrections.** `missingness` reports registered/eligible/pending/
  excluded counts and eligible fraction by design; `corrections` reports outcome
  records and experiments with multiple outcomes.
- **Fixed sensitivity analyses.** `first_outcome`, `qc_pass_only` and
  `precise_ci_only` change one choice at a time and report deltas versus the
  primary analysis. No p-values, no model selection and no "best" variant.
- **Archiveable artefacts.** `--out` writes canonical JSON with `generated_at` and
  a SHA-256 `content_hash` excluding the timestamp. `--html` writes one
  self-contained, escaped file with inline CSS and an inline SVG reliability plot.
- **Report schema v2.** `ntx-calibration-v2` adds `n_clusters`, `brier_skill_ci`,
  `underpowered_reasons`, `precision`, `corrections`, `missingness`, `sensitivity`,
  `by_kind` and `by_design`. No database migration or export change.
- **`docs/CALIBRATION.md`.** Expanded definitions, clustering, bootstrap caveat,
  sensitivity interpretation, artefact hashing and safe/unsafe statements.

## Not in this release

- Hierarchical/Bayesian calibration, calibration slope/intercept, cluster-size
  adjustment, multiple-comparison correction or correction for selective
  reporting.
- Proof that a prediction preceded an experiment, trusted registration time or
  external source verification.
- A rubric probability, replication probability, treatment effect or candidate
  ranking.
- Any claim that a small, clustered or selectively reported ledger is calibrated.

The report is a description of the rows that exist and of the analysis choices
that produced it. It is the input to a calibration discussion, not a conclusion.

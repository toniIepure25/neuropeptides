# ntx v0.16.0 - 2026-11-17

Effect rigor, operational safety and a stricter quality gate. The default
abstract-only report is unchanged; the changes target claims with several
effects, audit/quality payloads, backup/restore trust and API exposure.

## Highlights

- **Effect ownership.** When one sentence reports several effects, a 95% CI is
  attached only to the nearest preceding effect and only when it occurs before
  the next effect. Two effects no longer share one interval.
- **Versioned quantitative payloads.** New `ntx-quant-v1` objects carry an
  explicit schema and optional `warnings` (`multiple_effects`,
  `multiple_effect_types`). `validate_quant` checks finite values, ratio sign,
  correlation bounds, CI order, spans and exact text quotes. Claims without
  quantitative evidence keep `quant = {}` and old payloads remain valid.
- **Ambiguity instead of false precision.** Reconciliation schema
  `ntx-fulltext-report-v4` marks the `effect_comparison` as `ambiguous` and adds
  low-severity reason `effect_ambiguous` when one side has more than one
  comparable effect. It never silently picks the first effect or infers a
  clinical direction from a ratio.
- **Same-type effect error.** Evaluation reports effect value MAE only when both
  sides have the same effect type, plus per-type MAE and cross-type pair counts.
  Agreement output adds effect type kappa and value/CI agreement.
- **Quality payload v2.** `ntx-quality-v2` exposes
  `min_effect_coverage`/`require_gold`, ambiguous and unknown-effect counts, and
  warns when effect coverage is below the configured threshold or a claim is
  ambiguous. `ntx quality --require-gold` fails when a ready human gold is absent.
- **Effect audit.** `ntx audit sample --effects-only` stratifies by effect type
  and writes a separate `effect_verdict` (`correct`/`incorrect`/`unclear`);
  `ntx audit score` reports effect precision and per-type counts only from human
  verdicts.
- **Safer backups.** `ntx db backup` checks source integrity/schema, verifies the
  copied database before publishing it, records source/copy metadata and refuses
  to overwrite without `--force`. `ntx db verify` checks sidecar schema and byte
  count; restore re-verifies integrity, schema and counts before replacing.
- **API hardening.** Responses include `X-Content-Type-Options`, `X-Frame-Options`,
  `Referrer-Policy` and `Cache-Control`. A non-loopback bind now requires an
  `NTX_API_TOKEN` of at least 16 characters.

## Commands

```powershell
ntx audit sample --db build/demo.db --effects-only --out audit/worksheet.md --verdicts-out audit/verdicts.jsonl
ntx audit score --db build/demo.db --verdicts audit/verdicts.jsonl
ntx quality --db build/demo.db --min-effect-coverage 0.3 --require-gold --gold gold/v2/human.jsonl
ntx db backup --db build/demo.db --out backups/demo.db --force
ntx db verify --db backups/demo.db
$env:NTX_API_TOKEN = "a-16-character-secret"
ntx serve --db build/demo.db --host 0.0.0.0 --port 8765
```

## Limits

- Effect extraction and ambiguity detection are heuristics based on explicit
  labels; an unlabelled number is still ignored.
- `ambiguous` means the extractor cannot choose one comparable effect. It is a
  review trigger, not a claim that the study is contradictory or wrong.
- Effect audit precision is available only after a human fills verdicts; no
  precision number is inferred from blank templates.
- No human-annotated effect gold exists in the repository. Gold v2 remains a
  119-document frozen frame with a draft/non-human payload; double annotation is
  still external work.
- Full text stays local-only and is never committed, packaged or redistributed.
- The API is read-only and local-first; a token is a shared secret, not user
  accounts, roles or TLS termination.

# ntx v0.15.0 - 2026-11-17

Quantitative evidence, operational quality gates and a hardened local API. The
extractor now records explicit effect labels and context with exact-span
provenance; default reports remain abstract-only and byte-identical.

## Highlights

- **Conservative effect extraction.** SMD/Cohen's d/Hedges' g, mean difference,
  odds/risk/hazard ratios, beta, correlation and signed percent change are
  recognized only with an explicit label. Each effect keeps an optional 95% CI
  and explicit comparator, dose, route, timepoint and population quotes.
- **Schema v8.** `claims` and `fulltext_claims` gain `effect_type`, `effect_size`,
  `effect_ci_low`, `effect_ci_high` and `quant`. Migration is additive and
  idempotent; v7 rows keep `quant = '{}'`.
- **Effect-aware reconciliation.** Report schema `ntx-fulltext-report-v3` adds
  `effect_size_discrepancy`, `effect_type_mismatch` and context mismatches, plus
  an `effect_comparison` block per finding. Effect-size discrepancy requires
  comparable types, both CIs and non-overlap.
- **Effect-aware evaluation.** New metrics cover type accuracy on matched claims,
  value MAE, CI overlap, gold/prediction coverage and mismatches, including
  bootstrap and by-stratum output where coverage exists. Effect metrics are
  withheld when gold has no effects.
- **Quality gates.** `ntx quality` checks schema, provenance, effect coverage and
  gold readiness, returns a deterministic content hash and exits `1` only on a
  failed gate.
- **Dashboard.** `ntx dashboard` writes one self-contained HTML page with quality
  gates, counts, recent claims and reconciliation findings. No remote assets, no
  full-text redistribution.
- **Operations.** `ntx db backup` writes a sidecar with SHA-256, schema, counts and
  integrity; `ntx db verify` checks it; `ntx db restore` requires `--force` for an
  existing destination; `ntx doctor` runs integrity/schema/provenance checks.
- **API hardening.** New `/api/v1/quality` and `/api/v1/reconciliation` routes.
  A non-loopback bind requires `NTX_API_TOKEN`; requests require a constant-time
  Bearer/X-API-Token check and a Host allowlist (`NTX_API_ALLOW_HOSTS`).

## Commands

```powershell
ntx quality --db build/demo.db
ntx dashboard --db build/demo.db --out reports/dashboard
ntx db backup --db build/demo.db --out backups/demo.db
ntx db verify --db backups/demo.db
ntx db restore --backup backups/demo.db --db build/restored.db --force
ntx doctor --db build/demo.db
$env:NTX_API_TOKEN = "local-secret"
ntx serve --db build/demo.db --host 0.0.0.0 --port 8765
```

## Limits

- Effect extraction is heuristic and conservative; an explicit label is required
  and unlabelled numbers are ignored.
- Effect-size disagreement is a descriptive review trigger, not proof that either
  layer is wrong.
- No human-annotated effect gold exists yet; effect metrics are unavailable and
  must not be reported as validated performance.
- Default reports, discovery, calibration and ledger exports remain abstract-only;
  full-text claims are not promoted automatically.
- Full text remains local-only and is never committed, packaged or redistributed.
- The API is read-only and local-first; the token is a shared secret, not user
  accounts, authorization roles or TLS termination.

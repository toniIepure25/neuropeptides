# ntx v0.12.0 — 2026-11-15

Read-only source verification and hash-chained ledger checkpoints. The release
closes two explicit gaps from v0.11 without changing database schema v6 or ledger
export v3: stored metadata can be checked against external registries, and ledger
snapshots can be linked into a chain that exposes edits, gaps and reordering.

## Highlights

- **External source checks.** `ntx verify` resolves a document by DOI (Crossref)
  or PMID (PubMed), normalizes titles, compares years, maps retraction/concern/
  correction notices, and reports `verified`, `metadata_mismatch`,
  `retraction_drift`, `local_retraction`, `correction`, `unverifiable` or
  `unavailable`.
- **No silent downgrade.** A local retraction/concern/notice is never overridden by
  a registry response that lacks a notice. Reports are read-only and include the
  number of local claims attached to each document.
- **CI-friendly failure mode.** `--fail-on-drift` exits `1` for metadata mismatch
  or a newly detected retraction/concern. Offline cache misses, 404s and malformed
  responses are `unavailable`, not drift.
- **Offline-first.** All requests go through the existing HTTPS-only, cached,
  rate-limited transport; `--offline` never touches the network.
- **Ledger checkpoints.** `ntx ledger checkpoint` writes `ntx-checkpoint-v1` with
  sequence, `previous_hash`, `ledger_hash` and a self-hash. `--previous` is
  validated before writing, and existing files are never overwritten.
- **Chain audit.** `ntx ledger verify-checkpoints` checks the hash chain, continuous
  sequence, previous links and the current ledger hash. It detects edited,
  missing, reordered or post-checkpoint ledger state.
- **Report schema.** `ntx-source-verification-v1` canonical JSON has a SHA-256
  `content_hash` excluding `generated_at`; checkpoints use `ntx-checkpoint-v1`.
- **Docs and tests.** `docs/INTEGRITY.md` states the threat model. New tests cover
  source mapping, offline behavior, CLI output, chain construction and tampering.

## Not in this release

- Trusted timestamps, cryptographic signatures or a public transparency log.
- Proof that a prediction preceded an experiment or that a preregistration existed
  before an external event.
- Full-text verification, effect-size verification or automatic deletion/downgrade
  of evidence after a retraction report.
- Any claim that an absent retraction notice proves validity.

A checkpoint chain protects the snapshots it contains only after one of its hashes
is anchored outside the directory. A source report records what a registry returned
at check time, not a guarantee about the paper.

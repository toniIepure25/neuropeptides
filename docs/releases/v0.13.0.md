# ntx v0.13.0 — 2026-11-16

Optional open-access full-text evidence. The abstract pipeline and all existing
reports remain unchanged; PMC papers can now be fetched as JATS, parsed into
sections, and compared with their abstract claims under the same exact-span
invariant.

## Highlights

- **Local JATS snapshots.** `ntx fulltext fetch` resolves a PMC identifier through
  the Europe PMC `fullTextXML` endpoint and stores normalized body text, section
  offsets, source URL, licence, fetch time and SHA-256. Snapshots are immutable in
  v1; a second fetch reports `already_present`.
- **Section-aware claims.** `ntx fulltext extract` detects mentions over the full
  text, supplies JATS section offsets to the extractor, and keeps only Results,
  Discussion and Conclusions claims. Every claim is tied to the snapshot
  `text_hash` and its exact `start`/`end`.
- **Abstract/full-text comparison.** `ntx fulltext report` distinguishes
  `corroborated`, `fulltext_only`, `abstract_only` and `direction_conflict`, with
  section and per-document counts. `--fail-on-conflict` exits `1` when the same
  entity/outcome has opposite directions.
- **Separate integrity.** `ntx check` verifies abstract and full-text provenance
  separately. A full-text defect does not block abstract-only reports. Database
  schema is v7; ledger export remains v3 and has no full-text fields.
- **Defensive input handling.** XML `DOCTYPE`/`ENTITY` is rejected before parsing;
  HTTP and text sizes are capped; offline cache misses are reported as
  `unavailable`, not treated as invalid evidence.
- **No redistribution.** Full text is local database/cache state only. It is never
  committed, packaged or published.

## Commands

```powershell
ntx fulltext fetch --db build/demo.db --limit 10
ntx fulltext extract --db build/demo.db
ntx fulltext report --db build/demo.db --out reports/fulltext.json
ntx fulltext report --db build/demo.db --fail-on-conflict
ntx check --db build/demo.db
```

## Limits

- Only PMC open-access JATS; no publisher PDFs, supplementary files or
  comprehensive figure/table cell extraction.
- `corroborated` is a tuple match between stored layers, not proof that the
  abstract is correct or that the study is valid.
- Full-text claims do not enter default reports, discovery, calibration or the
  ledger automatically.
- Papers without a PMCID or available body remain outside the full-text layer.

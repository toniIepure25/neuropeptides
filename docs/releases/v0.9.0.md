# ntx v0.9.0 — 2026-11-14

Registration and result capture: a planned sample size can now be checked against
a reproducible two-arm worksheet, a registration can be supplied as a versioned
manifest, and external outcomes can be imported transactionally with idempotent
source ids. This release does not claim that an assumed effect is real, that a
registration was made before an experiment, or that an imported source is
authentic.

## Highlights

- **`ntx power`.** Two-arm parallel, equal-allocation worksheets for a mean
  difference (Cohen's d) or a two-proportion risk difference, with alpha,
  one/two-sided testing, target power and dropout. Canonical `ntx-power-v1` JSON
  with a deterministic `PW-...` id. Reference: d=0.5, alpha=.05, power=.8 gives
  63/arm (126 total); 10% dropout gives 70/arm (140 total).
- **Recomputation, not trust.** The ledger re-runs the worksheet before accepting
  it; altered `n_per_arm`, totals or `power_id` are rejected with exit code 2.
- **`ntx ledger register --file`.** Versioned `ntx-registration-v1` manifests with
  strict unknown-field rejection, optional `power`, `--dry-run`, and conflict
  checks against individual flags. `--power` also attaches a worksheet to
  flag-based registration.
- **Shortfall warning, not a block.** `power_check.meets_required` is reported;
  `n_planned` below the computed requirement remains registrable but must not be
  described as adequately powered.
- **Schema v6.** `experiments.power_json` and `outcomes.source_id` with a partial
  unique index per experiment/source. Migration from v5 is additive and preserves
  existing rows and append-only triggers.
- **`ntx ledger import-outcomes`.** JSON array, JSONL or wrapper input; one
  transaction; all experiment ids preflighted; identical repeats skip; conflicting
  repeats and duplicate source ids in one file fail; `--dry-run` writes nothing.
- **`ntx ledger outcome --source-id`.** Manual outcomes can carry the same external
  identity label.
- **Export schema v3.** Experiment power worksheets and outcome source ids are
  included in the SHA-256 content hash.
- **`docs/REGISTRATION.md`.** Formulas, reference values, manifest fields, import
  semantics, limitations and trust boundary.

## Not in this release

- Power for paired, crossover, cluster, time-to-event, ordinal or adaptive
  designs; continuity correction, stratification or covariate adjustment.
- Estimation of effect sizes from the corpus, prior outcomes or the literature.
- External registry lookup, DOI verification, trusted registration time or
  automatic outcome extraction from papers.
- Ranking, docking, MD, permeability, stability or immunogenicity prediction.
- Any claim that a small ledger is calibrated or that an imported result is
  authentic.

The import and registration layers feed the same append-only ledger. A correction
is still a new outcome row with a new `source_id`; history is not overwritten.
